リクエスト単位課金プロトコル (True Pay-Per-Request Protocol) を使うと、顧客に定額制のサブスクリプションを強制することなく、API リクエストやデジタルサービスの呼び出しごとに課金できます。顧客がリクエストを送信すると、システムが支払い条件を確認し、条件が満たされた時点で結果やデジタルサービスへのアクセスを解放します。

**主な用途:** 従量制の API アクセス、オンデマンドのデジタルサービス、1 回ごとに課金するソフトウェア機能など、顧客が実際にサービスを利用したときだけ支払いたい利用形態。

## 仕組み

1. リクエストの価格、受取人、利用規約を定めます。
2. API リクエスト、決済、デジタルサービスの提供を 1 つのフローでつなげます。
3. 支払い条件が満たされると、結果やデジタルサービスへのアクセスを解放します。

## 準備するもの

リクエスト単位の支払いの受け取りを開始する前に、以下の情報を準備してください。

- 課金対象とする API またはデジタルサービス
- 顧客に請求するリクエストごとまたは利用ごとの価格
- 受取人情報と利用規約

アカウント開設の要件と申込者の資格については、[お問い合わせフォーム](https://makeform.ai/e/iY978F0d?__mf_modal_embed=1) よりご連絡ください。

## 料金

顧客にリクエストごとに請求する価格と、Feezless の利用手数料は区別してください。支払いの受け取りを開始する前に、最新の取引手数料率と関連する費用について Feezless にお問い合わせください。

> **注:** 支払いリクエストの作成や振込証明の受領だけでは、支払いは確定しません。結果やデジタルサービスを提供する前に、確定済みの決済ステータスを確認してください。

## 次のステップ

API やデジタルサービスにリクエスト単位課金プロトコルを導入するには、ユースケース、想定されるリクエスト量、リクエストごとに請求する予定の価格を添えて、[お問い合わせフォーム](https://makeform.ai/e/iY978F0d?__mf_modal_embed=1) よりご連絡ください。
