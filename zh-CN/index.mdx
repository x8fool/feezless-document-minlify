## 按请求付费（True Pay-Per-Request Protocol）

**适用场景：** 按 API 请求收费和数字服务访问。

按每次 API 请求单独收费，而无需强制客户订阅包月套餐。在满足支付条件时开放结果或数字服务的访问权限。

- 按请求或使用次数收费
- 在同一流程中连接请求、支付和数字服务交付
- 在协议中明确价格、收款方和服务条款

## 支付链接

**适用场景：** 通过对话、社交媒体帖子和网站收款。

创建支付链接，并在客户常用的渠道中分享。客户打开链接即可付款，您可以跟踪付款状态。

- 通过聊天、社交媒体或网站分享链接
- 无需搭建商品目录即可收款
- 实时查看已收款项和待收款项

## 商品菜单

**适用场景：** 商品目录、餐厅菜单、咖啡馆和零售店铺。

将您的商品集中到单页在线店铺中。客户浏览菜单、将商品加入购物车，并在不切换页面的情况下完成支付。

- 在在线菜单中展示商品
- 将商品浏览、购物车和支付整合在一起
- 销售完成后自动扣减库存

## 门店收银系统（POS）

**适用场景：** 使用手机或平板电脑进行线下门店销售。

将移动设备用作收银界面，无需购买专用收银机。在销售的同时记录销售额并更新库存。

- 通过手机或平板电脑接单和收款
- 支持客户在收银时选择支付方式
- 售出商品时自动扣减库存

## 会员与权益系统

**适用场景：** 在客户付款时为其注册会员。

根据客户的首次付款发放会员卡，并通过客户选择的渠道发送。客户可通过链接自行设置 PIN 码并提供 PDPA 同意。

- 在支付流程中创建会员卡
- 向客户发送数字会员卡
- 让客户自行设置 PIN 码并提供同意

## 发票与账单支付

**适用场景：** 向客户收款并跟踪待付款项。

创建发票并向客户发送支付链接。客户可在线付款，您可以跟踪哪些发票已付款、哪些仍未支付。

- 创建并发送账单，无需另行手动准备单据
- 向客户发送在线付款链接
- 实时跟踪付款状态
